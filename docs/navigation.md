# 작업 중심 화면과 초기 설정

2026-11-05 내부 테스트0.38.0(62)에 반영한 화면 기준이다. 정식0.35.1 등 이전 설치본의 하단 작업·준비·설정 탭과 구분한다.

작업을 기본 화면으로 사용하며 하단 탭은 없다. 상단 설정 버튼으로 앱 설정을 열고 상단 뒤로 가기·Android Back·외장 키보드 Escape로 이전 화면에 돌아간다. 열린 다이얼로그는 먼저 닫으며 IME 조합 중 Escape로 화면을 닫지 않는다. 작업 화면으로 돌아오는 동작은 세션을 실행하거나 종료하지 않는다.

## 첫 실행과 기존 연결

- 저장된 연결 정보가 없으면 초기 준비 안내로 시작한다. Termux 설치·권한·브리지 연결·선택적인 에이전트 설치와 계정 연결을 안내한다. 터미널 사용에 에이전트 계정을 요구하지 않는다.
- 연결 정보가 있으면 실제 브리지 연결이 잠시 끊겨 있어도 작업 화면에서 재연결을 시도한다. 연결 정보가 있다는 사실만으로 준비가 검증됐다고 표시하지 않는다. 준비 안내의 연결 완료 표시는 기존처럼 실제 정상 연결 상태를 사용한다.
- 수동 페어링이나 빠른 연결이 성공하면 작업 화면으로 돌아간다. 계정별 모델 사용 가능 여부를 추측하거나 에이전트를 자동 실행하지 않는다.
- 연결 해제는 설정에서 제공한다. 앱의 연결 정보를 지우고 초기 준비 안내로 이동하되 Termux의 브리지나 실행 세션은 종료하지 않는다.

## 설정에서 관리

설정에는 브리지 업데이트/재시작, 재연결/앱 연결 해제, 에이전트 계정/프로바이더/API 키, 입력·언어·알림·음성 설정을 둔다. 초기 준비 화면의 별도 로그인·상태·버전 버튼을 반복하지 않고 에이전트별 ‘연결 관리’에서 설정과 같은 관리 다이얼로그를 연다. 설치·복구·어댑터 준비처럼 Termux에 필요한 작업은 설치 안내에 남긴다.

‘초기 설정 가이드’로 준비 안내를 다시 열 수 있다. 에이전트 관리 옆 설치 안내는 선택한 에이전트의 설명을 펼친다. 설정에서 가이드를 열고 뒤로 가면 설정의 이전 스크롤 위치로 돌아가며 다시 뒤로 가면 작업으로 돌아간다. 알림이나 프로젝트/세션 선택으로 작업에 직접 이동하면 보조 화면의 이전 경로를 비운다.

새 화면에서 브라우저 제어는 작업 화면의 요청 카드 또는 **상단 설정 → Firefox · Termux:X11 → 로그인 및 에이전트 제어**에서 사용자가 허용한다. 하단 탭이 있는 기존 설치본은 **하단 설정 → Firefox · Termux:X11 → 로그인 및 에이전트 제어**를 사용한다. 화면을 여는 것만으로 제어를 허용하지 않는다.

## 상태와 검증

페이지 이동은 기존 세션·네이티브 대화·작성 초안·대기열을 유지한다. 터미널 입력은 작업 화면에서만 활성화하며 기존 전체 화면 동작과 정상 완료 알림의 세션 이동을 유지한다. 넓은 화면의 프로젝트/파일 패널은 보조 화면에서 가리고 작업으로 돌아오면 기존 열림 상태로 표시한다.

`scripts/tests/test_page_navigation.cjs`에서 최초 진입·기존 연결/데모·뒤로 가기·가이드 스크롤 복원·세션/초안/대기열 유지·공유 관리 진입점을 검증한다. 전체 언어 검사는 새 문자열과 10개 언어 카탈로그를 확인한다. 관리 Firefox의 모의 화면은 `dist/navigation/`에 기록하며 Android WebView의 실기기 화면·키보드·TalkBack·알림 탭 동작 검증을 대체하지 않는다.

## 중지한 마지막 질문 다시 작성 (다음 빌드 소스)

응답 중지를 마치면 가장 최근 질문 옆의 연필 버튼으로 질문을 입력창에 불러올 수 있다. 내용을 수정하고 **보내기**를 눌러 새 메시지로 전송한다. 기존 질문·부분 답변과 에이전트 작업 결과는 유지된다. 버튼을 누르는 것만으로 전송하지 않는다. 작성 중인 다른 초안이 있으면 먼저 보내거나 비운 뒤 질문을 불러온다.

새 응답/전송 중이거나 다른 질문 이후에는 이전 중지 질문의 버튼을 제공하지 않는다. 명시적 중지 기록이 없는 가져온 대화에는 중지를 추측해 표시하지 않는다. Android와 iOS가 같은 소스를 사용하며 실제 앱 빌드·설치 반영 여부는 배포 기록을 확인한다.

## 디버그 모드 (2026-11-13 후속 소스, 미배포)

Android/iOS 모두 **상단 설정 → 맨 아래 개발자 옵션 펼치기 → 디버그 모드**에서 켠다. 항목은 작은 접힌 안내로 제공하며 기본은 꺼짐이다. 켜면 진단 로그 창에서 최근64개 로컬 상태 이벤트를 조회·새로고침·수동 복사·지우기할 수 있다. 일반 설정에는 로그 복사 메뉴를 표시하지 않는다. 연결이 없어도 진단 창은 사용할 수 있다.

디버그 모드에서는 대화 이외 버튼·라벨·안내·프로젝트 이름의 문구도 선택·복사할 수 있다. 프로젝트 이름의 길게 누르기 재정렬은 문구 선택을 위해 쉬며, 붙여넣기는 편집 가능한 입력란에서 기존 방식으로 처리한다. 안내/버튼을 편집하거나 명령·승인을 자동 실행하지 않는다. 끄면 선택 제한이 돌아오고 수집을 중지하며 저장된 진단을 지운다. 로그 사본은 창 닫기·백그라운드에서도 비운다.

진단은 고정된 상태/오류 코드·시각/수치만 기록하며 대화·터미널 출력·경로·URL·인증 정보는 기록하지 않는다. 자동 전송하지 않는다. 이 소스는 다음 앱 빌드에 반영하며 플랫폼별 실제 선택 핸들·복사 메뉴와 Xcode 검증은 별도다.

## 대기 메시지 수정 (2026-11-13 후속 소스, 미배포)

Android/iOS의 대기열에서 아직 제출되지 않은 메시지의 **수정**을 누른다. 브리지가 해당 항목을 확인하고 대기열을 일시정지하면 별도 입력창이 열린다. 수정 저장은 같은 항목/순서를 유지하며, 전송은 **대기열 재개**를 눌러 진행한다. 취소해도 원문과 일시정지를 유지한다. 일반 입력창의 초안은 바뀌지 않는다.

이미 전송/방향 수정 중이거나 전달 여부가 불명확한 항목은 수정할 수 없다. 다른 화면에서 먼저 바꿨다면 덮어쓰지 않고, 수정 초안을 보존하며 다시 연 창에서 대기열의 현재 내용을 비교할 수 있다. 화면 전환이나 연결 실패로 수정 초안을 자동 제출하지 않는다. 새 앱과 Android 브리지0.25.2 또는 새 iOS 내장 브리지가 필요하다.

## 에이전트 관리 통합 (2026-11-13 후속 소스, 미배포)

Android/iOS 모두 **상단 설정 → 에이전트 관리 → 관리 열기**에서 설치 상태·계정 연결·프로바이더·버전 업데이트를 관리한다. 초기 설정의 **에이전트 준비 → 관리 열기**도 같은 화면을 연다. 초기 설정 뒤에도 재로그인·추가 설치·복구를 위해 같은 관리 기능을 유지하며 중복 화면을 비활성화하는 방식을 쓰지 않는다.

관리 화면 아래 **설치·복구 및 문제 해결**을 펼치면 선택한 에이전트의 기존 상세 안내를 볼 수 있다. 준비된 설치는 기본 접힘이며 미설치/복구가 필요한 경우 최신 조회 뒤 안내를 펼친다. 설치 상태는 인증/모델 접근 상태와 구분한다. Android는 기존 Termux 명령/Claude 복구 경로를 유지하고 iOS는 내장 환경의 설치·복구 작업만 이곳에 둔다. 로그인·버전은 공통 관리 기능을 사용한다.

단순 화면 이동이나 안내 펼치기로 설치/인증/기존 세션 종료를 실행하지 않는다. iOS 설치 작업을 직접 요청해 새 터미널이 확인되면 그 화면으로 이동하며 실패/다른 프로젝트 이동 시 현재 관리를 임의로 닫지 않는다. 이 구조는 다음 앱 빌드에 반영한다.
