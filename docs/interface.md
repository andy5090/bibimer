# Bibimer 화면·응답 렌더링

## 사이드바 프로젝트 순서 (2026-10-15, 미배포)

프로젝트 이름 옆 **⋯ → 프로젝트 순서**의 **위로 이동 / 아래로 이동**으로 한 칸씩 정렬한다. 현재 위치와 전체 개수를 표시하고 맨 위/아래의 해당 방향은 비활성화한다. 프로젝트가 접혀 있어도 메뉴를 사용할 수 있으며 정렬 후 메뉴·사이드바와 현재 선택을 유지한다. 활성/보관 세션·워크트리·초안·대기 승인·프로세스에는 영향을 주지 않는다.

순서는 프로젝트 이름/경로가 아닌 등록 ID 기준이며 Termux 브리지의 기존 프로젝트 메타데이터에 저장한다. 앱·브리지 재시작 후에도 유지하고 신규 등록/클론 프로젝트는 끝에 추가하며 등록 해제 시 나머지 순서를 유지한다. 심사용 예제는 별도 메모리 목록만 정렬한다. `project_ordering` 기능을 제공하는 새 브리지가 필요하며 구형 브리지는 이동을 비활성화하고 업데이트 안내를 제공한다. APK 반영·실기기 검증은 남아 있다.

## 클론·프로젝트 열기의 기본 폴더 (2026-10-15, 미배포)

마지막으로 확정한 위치를 앱 재실행 후에도 기억한다. GitHub 클론에서 선택한 상위 폴더를 다음 클론/새 프로젝트 생성의 기본 위치로 사용한다. 기존 `/projects/app-a`를 열거나 새로 만들었다면 다음 생성 경로는 `/projects/`, 프로젝트 탐색 시작 위치는 `/projects/app-a`다. 두 흐름이 생성 기준 위치를 공유하며 폴더 이름은 사용자가 입력한다.

폴더 찾아보기의 목록 첫 행은 `↰ ..` 상위 폴더 이동이다. 현재 폴더의 부모 경로로 이동하며 최상위 `/`에서는 숨긴다. 페이지를 더 불러와도 첫 행을 유지하고 홈·숨김 폴더·선택 동작은 그대로 제공한다.

탐색 이동·취소만으로는 저장 위치를 바꾸지 않는다. 경로를 직접 입력하면 해당 입력을 탐색 시작 위치로 우선하고, 등록/클론 수락 후 실제 Termux 경로를 저장한다. 클론 재시도와 실행 중 입력은 보존한다. 저장된 탐색 위치가 사라지면 기존 홈 fallback을 제공한다. Android 비공개 설정에 경로 두 개만 보관하며 심사용 예제는 정상 설정과 분리한 화면 메모리를 사용한다. 실제 Android 저장/재실행 검증과 APK 반영은 남아 있다.

## 우측 파일·Git 사이드바 (0.14.0)

상단 오른쪽 버튼으로 작업 폴더 패널을 열고 **Files / Git status / Git history** 세 아이콘 탭으로 전환한다. 영어·한국어, 아이콘 접근성 이름과 마우스 도움말을 제공하며 외부 키보드는 좌우 방향키·Home/End로 탭을 선택한다.

**0.14.1 APK:** 상단 오른쪽 버튼도 현재 선택된 탭의 아이콘을 표시한다. 최초는 Files 폴더 아이콘이며 탭 전환 즉시 변경하고 패널을 닫아도 유지한다. 버튼의 접근성 이름과 도움말도 선택 탭·언어에 맞춘다. 이 변경은 기존 브리지 0.14.0을 사용한다.

- **Files:** 현재 프로젝트 또는 선택 세션/새 세션의 실제 워크트리를 기준으로 폴더를 탐색한다. 하위 폴더의 목록 첫 행은 상위 폴더 이동이며 작업 폴더 루트에서는 표시하지 않는다. 루트·숨김 파일 전환, 200개씩 더 보기를 제공한다. 파일 선택 시 아래 전체 화면 뷰어를 연다. `.git` 내부·심볼릭 링크·특수 파일은 열지 않는다. 텍스트 미리보기는 앞 128KiB까지 표시한다.
- **Git status:** 브랜치, 로컬에 기록된 upstream/ahead/behind, staged·working tree·미추적 파일과 충돌을 표시한다. 변경 파일을 선택하면 staged/working diff를 전환하고 미추적 파일은 내용 또는 폴더를 연다.
- **Git history:** 현재 HEAD 기준 커밋 목록을 50개씩 조회하고 커밋 메타데이터·통계·patch를 표시한다. 더 보기 중에는 처음 조회한 revision을 유지하며 새로고침으로 최신 HEAD를 읽는다. 등록한 폴더가 저장소의 하위 폴더이면 해당 경로의 이력·변경만 표시한다. diff·커밋 상세는 앞 256KiB까지 표시하고 잘림을 안내한다.

창 너비 **1,280px 이상**에서는 접을 수 있는 320~400px 우측 패널을 본문 옆에 고정한다. 왼쪽 프로젝트 패널과 함께 열 때는 왼쪽 폭을 280~300px로 조절한다. 그보다 좁은 창에서는 너비 최대 460px/화면 94%의 모달 서랍을 사용한다. 넓은 창에서 좁은 창으로 바뀌면 패널을 닫고 열기 버튼에 포커스를 돌린다. 닫기·바깥쪽 탭·Escape 및 모바일 Back을 지원한다. 낮은 창의 새 세션 설정 영역은 스크롤되어 하단 메뉴를 가리지 않는다.

열기·탭/경로 전환·새로고침 때 조회하고 조회 시각을 표시한다. 실시간 파일 감시는 하지 않는다. 프로젝트·워크트리·브리지 인스턴스 변경 또는 연결 중단 시 이전 조회를 무효화한다. 세션 프로세스·작성 중인 입력·승인 상태는 유지하며, 파일·Git 내용은 로그나 브리지 메타데이터에 저장하지 않는다. 모든 탭은 읽기 전용이며 파일 편집·fetch·stage·commit은 제공하지 않는다. 오류·빈 폴더·Git 저장소 아님·구형 브리지 안내와 재시도를 제공한다.

검증은 임시 Git 저장소·실제 격리 브리지와 브라우저 네이티브 대역으로 수행했다. 1600px 좌우 고정 패널, 768px 모달, 320×460px 작은 창, 프로젝트/워크트리 전환·지연 응답 무효화·초안/프로세스/인덱스 보존을 확인했다. **앱·브리지 0.14.0으로 빌드했으며 APK 서명·내장 파일·설치 스크립트 추출 검증을 마쳤다.** 실제 Android WebView·DeX·태블릿 터치/키보드 검증과 APK 설치·운영 브리지 적용은 남아 있다.

## 전체 화면 파일 뷰어

파일 탐색기와 Git status의 미추적 파일을 누르면 전체 화면 다이얼로그를 연다. 모바일 파일 사이드바와 큰 화면의 고정 패널은 뷰어 아래에서 열린 상태로 유지한다. 파일명·프로젝트/워크트리 기준 상대 경로, **Preview / Raw source / Reload file / Open in Android app**과 닫기 버튼을 제공한다. 닫기·Back/Escape는 뷰어부터 닫으며 탐색기를 통해 열었다면 같은 폴더·스크롤 위치·선택한 파일의 포커스로 돌아간다. 다시 Back/Escape를 누르면 모바일 탐색기를 닫는다. 세션·입력 초안·대기열·승인은 그대로 유지한다. Git diff·커밋 상세는 기존 사이드바에서 확인한다.

이 탐색 동작 개선은 2026-10-14 **0.17.1(33) 내부 테스트**로 배포한 뒤 사용자의 설치·정상 동작 보고를 받고 같은 번들을 정식 출시했다. Console에서 오후 4:17 게시·100% 출시를 확인했다. 영어·한국어 320px/393px 및 1600px 브라우저에서 격리된 실제 브리지로 확인했으며 실제 Android WebView·시스템 Back·외부 앱 복귀는 테스트 설치본에서 별도 검증한다.

- 코드·설정 파일은 설치한 highlight.js의 지원 언어에 맞춰 구문을 강조하고 줄바꿈 전환·복사를 제공한다. 미지원 언어와 16,000자를 넘는 코드도 원문을 표시한다.
- Markdown은 기존 GFM 렌더러로 제목·목록·표·코드 등을 표시한다. `mermaid` 코드 블록은 다이어그램으로 표시하며 원본 보기에서 전체 Markdown 소스를 확인한다.
- HTML은 정적 미리보기와 원본 보기를 제공한다. sandbox iframe과 CSP로 스크립트·네이티브 API 실행·외부 리소스·링크 이동·폼 전송을 막는다. 인라인 CSS는 표시한다. 상대 CSS·이미지와 JavaScript를 실행하는 웹앱 프리뷰는 지원하지 않는다.
- `.mmd`·`.mermaid` 파일은 내장 Mermaid 12.1.0으로 그린다. SHA-512를 고정한 라이브러리·라이선스를 앱에 포함하고 최초 다이어그램에서 로드한다. 16,000자/500개 간선 제한, strict 모드, 설정 지시문·내장 HTML/이미지·클릭 명령 제한을 적용한다. 렌더링 실패 시 안내와 원본을 표시한다. SVG 결과도 별도 sandbox iframe에 표시한다.
- Word·PowerPoint·Excel 및 이미지 파일은 파일 선택으로 설치된 Android 앱에 열기를 요청한다. **PDF도 이번 구현은 외부 앱을 사용한다.** 자체 PDF 렌더러·페이지 탐색·확대·검색·메모리 관리를 추가하는 대신 기존 뷰어의 기능을 활용한다. 지원 앱이 없으면 안내 후 다시 열거나 닫을 수 있다.

바이너리/비 UTF-8 파일은 자체 렌더링 대신 외부 앱 열기를 안내한다. 잘린 HTML·Markdown·Mermaid는 일부 문서를 완성된 미리보기로 오해하지 않도록 원본 텍스트로 표시한다. 외부 앱 열기에는 기존 네이티브 읽기 전용 ContentProvider와 64MiB 전송 제한을 적용한다. 프로젝트/워크트리/브리지 변경 시 뷰어를 닫고, 닫기·새 조회 뒤 이전 응답과 다이어그램 결과를 무효화한다. 조회 결과는 로그·메타데이터에 저장하지 않는다.

실제 임시 브리지와 Chromium의 Android API 대역에서 렌더링·원본 전환·외부 앱 요청 경로·오류·320px/393px/1600px·영어/한국어·초안/실행 세션/인덱스 보존을 확인했다. 실제 Android WebView의 srcdoc/CSP·뒤로 가기·설치된 문서/이미지/PDF 앱 호출은 새 APK에서 검증해야 한다. 이번 변경은 기존 workspace_inspector/file_links 브리지를 사용하며 브리지 소스 변경은 없다.

## DeX·태블릿 반응형 화면 (0.13.1)

기기 이름 대신 **앱 창의 CSS 너비와 높이**로 배치를 선택한다. DeX 창 크기 변경·태블릿 분할 화면에서도 같은 기준을 사용한다.

- **700px 미만:** 기존 휴대폰 화면과 모달 사이드바를 유지한다.
- **700px 이상:** 좌우 여백 24px, 대화 본문 15px, Chat 최대 너비 920px를 적용한다. 대화와 입력창을 같은 축에 맞추고 Settings·Setup은 최대 840px로 제한한다. 터미널은 가용 폭 전체를 사용한다. 높이가 650px 이상일 때 입력 영역·전송 버튼·상하 여백을 넓히며 여러 줄 초안은 최대 160px까지 자란다. 낮은 창·키보드 표시 중에는 기존 압축 배치를 사용한다.
- **1,000px 이상:** 왼쪽에 280~320px의 프로젝트·워크트리·세션 패널을 기본 표시한다. 상단 사이드바 버튼 또는 닫기 버튼으로 접을 수 있고, 세션/탭을 바꿔도 열린 패널을 유지한다. 대화와 목록은 각각 스크롤하며 패널이 입력·전송을 가리지 않는다. 에이전트·모델·권한 선택은 기존 자체 하단 시트를 유지한다.

휴대폰 모달과 넓은 화면의 비모달 패널은 같은 DOM을 사용한다. 전환 때 프로젝트 펼침·세션별 초안·승인 상태를 재생성하지 않는다. 작은 창으로 바뀌면 패널을 닫고 필요할 때 모달로 다시 연다. Android 뒤로 가기는 열린 선택/관리 창을 먼저 닫으며 고정 패널만으로 가로채지 않는다. 패널 안의 Escape는 패널을 접고 열기 버튼으로 포커스를 돌린다. 접힘 선택은 현재 화면 메모리에 유지하며 앱 재실행 시 큰 창의 기본값은 펼침이다.

브라우저 대역에서 320/393px 휴대폰, 768/820px 태블릿 세로, 1024/1440/2560px 가로 화면과 1100×460의 낮은 창을 검증했다. 대화·입력 정렬, 전송 버튼 노출, 페이지 가로 넘침 없음, 모달 ↔ 고정 패널 전환, 포커스·초안 유지, 실제 격리 브리지의 세션 왕복·승인 보존을 확인했다. 실제 DeX·태블릿의 Android WebView·IME·디스플레이 이동은 설치 후 검증한다.

## 0.4.0 방향

코딩 에이전트의 답변과 작업 과정을 읽는 공간을 중심에 둔다. 12px 화면 여백, 4~8px 제어 요소 간격, 작은 헤더·상태 행을 사용한다. 등록·전송·승인 같은 주요 동작은 44px 안팎의 터치 영역을 유지한다. 393×780 브라우저 검증 화면에서 실행 중 대화 영역의 높이가 400px 이상인지 확인한다. 실제 Android 시스템 바·키보드를 포함한 화면은 별도 검증한다.

배경은 흑연색 계열, 본문은 밝은 중성색, 주요 동작과 진행 상태는 민트색이다. 파일 추가·삭제는 초록·붉은 색과 `+`·`-`를 함께 사용한다. 색만으로 상태를 구분하지 않는다. 실행 프로세스 상태와 응답 상태는 계속 별도로 표시한다.

0.6.1은 공통 입력창 아래에 8px 마진을 추가해 하단 조작 영역과 간격을 둔다. Chat·PTY 및 높이가 작은 화면에도 같은 여백을 적용한다.

0.10.0에서는 권한·Fast 아래의 반복 안내를 숨겨 대화 영역을 확보한다. 저장 중이거나 브리지 업데이트가 필요할 때만 상태를 표시하고, 다음 입력·세션 적용 시점과 마지막 선택 저장 설명은 ⓘ 세션 설정에 둔다. 하단 내비게이션과의 여백은 유지한다.

`Responding / 응답 중`은 민트색 배경·굵은 글자와 작은 회전 링으로 강조한다. 사이드바와 세션 관리에서도 같은 회전 표시를 사용한다. 연결된 Chat의 실제 턴 상태가 `running`일 때만 표시하고 응답 완료·실패·승인/질문 대기·연결 끊김에서는 제거한다. 모션 줄이기 설정에서는 회전 없이 고정 링과 색상으로 표시하며, 스크린리더가 읽는 기존 상태 문구는 유지한다.

## 자체 선택 목록 (0.10.0)

프로그램·Chat/PTY·입력창 아래 권한·Enter 동작·언어·가져오기·권한 설명창의 선택 목록을 앱 내부 하단 시트로 통일한다. 선택한 행에는 민트색 배경과 체크 표시를 함께 사용한다. 권한별 설명, Enter 동작 설명을 해당 목록에 표시하며 사용할 수 없는 항목은 선택할 수 없다. 입력창 아래 권한 트리거는 테두리 없는 텍스트 형태를 유지한다. 프로젝트 전환은 이후 아래의 사이드바로 옮겼다.

목록 행을 누르면 즉시 선택하고 닫으며 닫기 버튼·시트 밖 탭·Escape는 선택을 유지한다. 외부 키보드의 방향키·Home/End·문자 검색으로 이동하고 Enter/Space로 선택한다. 닫은 뒤에는 원래 선택 버튼으로 포커스를 돌린다. 긴 목록은 시트 안에서 스크롤하며 선택 행부터 보여준다. 목록을 연 사이 프로젝트·세션이 바뀌거나 항목이 제거/비활성화되면 이전 항목을 적용하지 않는다.

2026-10-03 브라우저 검증에서 영어/한국어, 320~393px 화면, 120개 항목·긴 경로, 중첩 팝업, 저장 실패 복원, 상태 갱신 중 포커스 유지를 확인했다. 0.10.0 APK에 포함했으며 Android WebView의 실제 터치·뒤로 가기·TalkBack은 설치 후 검증한다.

## 모델·추론 수준·에이전트 행 (0.10.0)

입력창 아래에 **Agent / Model / Reasoning / ↻** 행을 추가하고 기존 권한·Fast 행을 이어 둔다. 선택은 모두 자체 하단 시트를 사용한다. 좁은 화면에서는 현재 모델 이름을 한 줄로 줄이고 목록을 열면 전체 이름과 설명을 읽을 수 있다. 에이전트 목록에는 마지막 선택 세션의 실행·응답·승인 대기 상태를 함께 표시한다.

모델은 제공자의 네이티브 목록에서 조회하고 선택한 모델이 지원하는 effort/variant만 추론 목록에 표시한다. 모델 변경은 추론 수준을 기본값으로 초기화한다. 목록 조회 중·실패·빈 목록·브리지 업데이트 필요를 별도로 안내하고 ↻로 재조회한다. 목록에서 사라진 저장 모델을 임의의 다른 모델로 바꾸지 않는다. Chat 선택은 다음 메시지, PTY 선택은 다음 실행에 적용한다. OpenCode PTY 추론 선택은 비활성화하고 자체 메뉴를 안내한다.

에이전트 전환은 같은 프로젝트 내 각자의 마지막 선택 세션을 복원한다. 이전 프로세스·대기열·승인을 유지하며 입력/질문 초안도 세션 ID로 구분한다. 기존 세션이 없는 에이전트에서는 시작·가져오기 화면을 표시한다. 표시 언어·입력키 동작은 기존 앱 공통 설정을 사용한다.

## 프로젝트·워크트리·세션 사이드바 (앱·브리지 0.10.0)

상단 왼쪽 버튼으로 화면 너비의 최대 88%인 사이드바를 열고 닫는다. 프로젝트를 한 목록에 나열하고 각각 접고 펼친다. 실제 Git 워크트리가 있으면 작업 폴더별 하위 목록에 세션을 묶고 `+ New session`·저장된 세션 가져오기를 제공한다. 폴더 추가는 하단 `Project Add`, 프로젝트 열기는 이름 옆 ↗를 사용한다. 목록은 안쪽에서 스크롤하며 현재 세션·프로젝트와 실행 수를 표시한다. 펼침·포커스·스크롤은 상태 갱신 중 유지한다.

대화창 아래의 `Stop this session`을 제거했다. 화면 상단 또는 목록의 세션 행에서 ⋯를 열면 이름 변경·보관/복원·종료·BIBIMER 목록 삭제·가능한 원본 이어하기를 제공한다. 보관은 실행을 유지한 채 보관함으로 옮기고, 목록 삭제는 종료된 세션에만 허용하며 확인창에서 대상 이름과 원본 유지 범위를 설명한다. 보관된 실행도 프로젝트의 실행 수에 포함한다. 현재 응답만 중단하는 기존 버튼은 유지한다.

새 세션을 만들 때 기존 프로세스와 대화를 유지한다. 같은 에이전트의 여러 세션을 오갈 수 있고 입력/질문 초안은 세션 ID로 구분한다. 원본 기록은 제공자 CLI에, 목록·이름·보관 상태는 브리지 메타데이터에 남긴다. 브리지 재시작 후 기존 프로세스를 복원했다고 표시하지 않으며 Chat은 원본 이어하기를 사용한다.

닫기·바깥쪽 탭·Escape로 사이드바를 닫는다. **모바일 스와이프 닫기(소스 반영, 다음 APK 대기):** 왼쪽 프로젝트 목록은 왼쪽으로, 오른쪽 파일·Git 패널은 오른쪽으로 밀어 닫는다. 짧은 드래그는 복귀하며 세로 스크롤·코드 가로 스크롤·긴 누르기·두 손가락 터치를 유지한다. 큰 화면의 고정 패널은 스와이프로 닫지 않는다. Android 13 이상에서는 열린 대화상자나 다른 페이지가 있을 때만 `OnBackInvokedCallback`을 등록하고, 이전 버전에서는 Back을 WebView UI에 전달한다. [Android 공식 Back 안내](https://developer.android.com/guide/navigation/custom-back/predictive-back-gesture)에 맞춘 소스이며 실제 시스템 제스처·IME·TalkBack 검증은 다음 APK 설치 후 진행한다.

## 프로젝트 설정 (앱·브리지 0.11.0)

각 프로젝트 이름 옆 **⋯**는 프로젝트를 펼치지 않고도 사용할 수 있다. **Project settings(프로젝트 설정)**에서 이름을 변경하거나 폴더 경로를 확인·복사하고 **Remove project(프로젝트 등록 해제)**를 선택한다. 이름은 두 줄까지 표시해 긴 이름도 메뉴 버튼을 밀어내지 않는다. 프로젝트 폴더를 이동하거나 경로를 바꾸지는 않는다.

등록 해제 확인창에 대상 이름과 유지되는 데이터 범위를 명시한다. BIBIMER 프로젝트·세션 목록만 제거하며 실제 폴더·워크트리·원본 에이전트 기록은 유지한다. 보관함을 포함해 실행 중인 세션이 있으면 버튼을 비활성화하고 종료가 필요함을 안내한다. 서버에서 거절된 경우 확인창에 오류를 표시해 재시도할 수 있다. 구형 브리지에서는 변경 버튼을 비활성화하고 업데이트를 안내하며 폴더 경로는 계속 복사할 수 있다.

## 대기 메시지 Steer (앱·브리지 0.10.0)

Codex의 대기 메시지 행에 **Steer / Remove**를 함께 둔다. 진행 중인 응답이 있을 때 Steer를 활성화하며, 전달 중인 항목에는 **Steering…**을 표시하고 중복 조작을 막는다. 수락된 항목만 목록에서 제거한다. 거절은 실패 상태로, 확인 응답 유실은 전달 여부 불명으로 남기고 대기열을 일시정지한다. 입력창의 작성 내용은 변경하지 않는다. Claude·OpenCode와 `queue_steer`가 없는 브리지에는 기존 취소 버튼만 표시한다. 기존 입력창 Steer도 유지한다.

응답 중단·입력창 방향 수정·대기 메시지 방향 수정 버튼은 선택 메뉴와 같은 색의1px 테두리와8px 둥근 모서리로 버튼 영역을 표시한다. 응답 중단의 붉은 글자와 비활성 상태의 흐린 표시는 유지한다.

## 쉬운 Termux 연결 (0.10.0 / 실기기 검증 대기)

Setup은 **Termux 설치 → 설정하고 연결 → 에이전트 준비** 순서로 제공한다. 기본 동작은 **Set up and connect** 하나로 합치고 수동 파일 저장·연결 코드 입력은 접을 수 있는 **Manual setup and pairing**에 보관한다. 최초 권한 설명·앱 권한 열기·Termux 연동 허용 명령 복사·Termux 열기를 같은 카드에서 제공한다. 권한을 자동으로 허용했다고 표시하지 않는다.

준비 중에는 중복 요청을 막고 상태를 표시한다. 권한 부족·Python/브리지 설치 실패·연결 실패·결과 대기를 구분하며 실패 후 재시도와 수동 경로를 제공한다. 연결 코드는 화면에 노출하지 않고 연결 완료 후 Work로 이동한다. 완료 상태는 저장 성공을 뜻하며 현재 접속 상태는 기존 헤더에서 별도로 표시한다. 영어 기본·한국어를 지원하고 320/360px 화면에서 권한 버튼을 줄바꿈한다.

## 앱 설정 (0.9.0)

하단 내비게이션은 **Work / Setup / Settings**를 제공한다. Setup은 Termux 준비·연결 안내, Settings는 **Enter key**와 **Language** 선택 화면이다. 연결 전에도 설정할 수 있고 화면 왕복은 실행 세션·입력 초안을 유지한다. 작은 화면에서는 설정 영역만 스크롤하며 하단 내비게이션을 고정한다.

Enter는 기본 **New line(줄바꿈)**이다. **Send(보내기)**를 선택하면 Enter로 전송하며 응답 중에는 대기열에 추가한다. Shift/Ctrl/Meta/Alt+Enter는 항상 줄바꿈하고 한글 조합 중 Enter는 전송하지 않는다. 설정은 모든 프로젝트·세션의 공통 입력창에 적용하며 키보드 힌트를 함께 바꾼다. PTY 직접 입력·특수 키는 기존 동작을 유지한다. 권한·Fast는 계속 입력창 아래에서 바로 선택한다.

## 응답 완료 알림 (0.11.0 / 실기기 검증 대기)

Settings의 **Response notifications(응답 완료 알림)**에서 알림을 켜고 끈다. 기본 설정은 켜짐이며 첫 연결 후 Android 13 이상에서 알림 권한을 요청한다. 허용 전에는 서비스·완료 알림을 시작하지 않으며 거절해도 대화는 계속 사용할 수 있다. 권한/채널 차단 상태에는 **Android notification settings** 버튼을 제공한다. 구형 브리지는 업데이트 안내를 표시한다.

선택하지 않은 프로젝트·보관한 세션을 포함해 Codex·Claude·OpenCode Chat의 정상 응답 완료마다 알린다. 연속 대기열도 각 완료를 구분한다. 0.11.0 설치본의 알림 제목은 프로젝트 이름, 내용은 응답 완료와 세션 이름/에이전트다. **0.11.1 APK에서는 본문을 완료된 답변의 최대 180자 미리보기로 바꾸고 세션 이름/에이전트를 보조 문구로 분리했다. 브리지 0.11.1도 필요하다.** Markdown 기호·링크 문법·제어 문자를 정리한 원문 발췌이며 추가 모델 요약을 호출하지 않는다. 답변이 없으면 일반 완료 문구를 표시한다. 도구/명령 출력·추론·이전 턴 본문은 발췌하지 않는다. 잠금 화면 공개 버전은 BIBIMER·응답 완료만 표시한다. Android 사용자 설정이 실제 표시·소리·진동 방식을 결정한다.

알림을 누르면 해당 프로젝트·세션으로 이동하고 현재 입력 초안은 유지한다. 세션 실행·잃어버린 프로세스 복원·승인은 자동으로 하지 않는다. 삭제된 세션이면 안내를 표시한다. 지속 알림의 **Turn off alerts**는 완료 알림만 끄며 에이전트 세션은 종료하지 않는다.

| 내용 | 표시 방식 |
| --- | --- |
| 에이전트 답변 | 제목 계층, 문단, 강조·기울임·취소선, 중첩 목록·체크리스트, 인용·구분선, 정렬 가능한 GFM 표 |
| 코드 | 명시된 언어의 구문 강조, 코드만 복사, 가로 스크롤 또는 줄바꿈 전환 |
| 명령·도구 | 작은 접이식 행에 명령과 상태를 표시. 명령은 성공/실패를 구분하고 실패 시 실패 코드를 표시하며, 펼치면 명령·출력 확인 |

| 계획 | 완료·진행·예정 단계와 완료 개수. 에이전트가 제공한 공개 요약은 Agent summary / 에이전트 요약으로 별도 접이식 표시. 본문과 단계가 없는 요약은 숨김(0.13.0 APK 포함) |
| 승인·질문 | 별도 응답 카드. 요청 명령과 변경 미리보기·추가 권한 내용을 보존하고 사용자에게 명시적인 응답을 받음 |

명령의 구조화된 상태가 완료이고 코드가 0이면 초록색 **성공**만 표시한다. 명시적인 실패 상태이거나 완료된 명령의 코드가 0이 아니면 **실패**와 **실패 코드 127**처럼 코드 이름·숫자를 함께 표시한다. 실패 이벤트가 코드를 전달하지 않으면 **실패 코드 미제공**으로 표시한다. 완료 상태라도 코드가 없으면 성공으로 추정하지 않으며 진행 중·중단 상태와 실제 세션/프로세스 상태는 유지한다. 이 표시는 해당 명령의 결과이며 전체 작업의 성공 판정이 아니다.

이전 내용을 읽는 동안 새 항목이 추가되면 읽던 위치를 유지하고 **Jump to latest**로 최신 응답으로 돌아간다. 같은 항목이 갱신되거나 표시 언어가 바뀌어도 접기·코드 줄바꿈 상태를 유지한다. 입력 초안과 질문 초안은 기존 프로젝트별 메모리 보관 방식을 사용한다.

외부 HTTP(S) 링크는 탭했을 때 Android 브라우저로 연다. 로컬 이미지·파일 경로 링크는 **Open in Android app / Android 앱으로 열기**로 표시하고 탭하면 지원하는 외부 Android 앱으로 연다(0.15.0 APK 포함, 앱 설치·브리지 적용 대기). 파일 준비 중에는 상태를 표시하고 중복 요청을 막는다. 파일 누락·접근 제한·64MB 초과·지원 뷰어 없음은 선택 언어로 안내한다. 앱 내부 파일 편집기나 이미지 뷰어를 제공하는 것으로 표시하지 않는다. 이미지 참조는 설명과 링크로 표시하며 자동으로 내려받지 않는다. HTML은 문자 그대로 표시한다. 수식·Mermaid·실행 가능한 HTML 미리보기는 이번 범위에 포함하지 않는다.

## 렌더러와 안전한 출력

`marked` 15.0.12의 lexer로 GFM 토큰을 읽고 `rich-text.js`가 허용한 DOM 요소만 만든다. Markdown에서 HTML을 생성해 삽입하지 않는다. 코드 구문 강조는 `highlight.js` 11.11.1이 이스케이프한 코드에 적용한다. 등록된 언어가 없거나 16,000자를 넘는 코드도 원문 표시·복사를 제공한다. 두 라이브러리는 SHA-512를 고정한 배포본과 라이선스를 APK에 포함하고 런타임 CDN에 의존하지 않는다.

파일별 변경과 계획 단계는 브리지의 구조화된 이벤트에서 전달한다. PTY 출력을 분석해 답변이나 도구로 분류하지 않는다. 기존 브리지의 평문 미리보기 필드도 표시할 수 있다. 파일 변경 미리보기가 잘린 경우 이를 알리며 대화 내용·계획·diff를 메타데이터 파일에 저장하지 않는다.

## 텍스트 로고와 서체

텍스트 로고는 **BIBIMER**로 표기하고 [Space Grotesk Bold](https://github.com/floriankarsten/space-grotesk)를 사용한다. 각진 글자 형태와 기존 B 심벌을 맞추고, 18px·700 굵기·0.065em 자간으로 좁은 헤더에서도 읽히도록 배치한다. 앱 창 제목·런처 이름·버전 표시도 대문자로 통일한다. 일반 영어·한국어 UI는 기기의 system-ui 서체로 읽기 편하게 유지하고, 코드·PTY는 기존 고정폭 서체를 사용한다.

41,780바이트 WOFF2 원본과 SIL OFL 1.1 라이선스를 `assets/fonts/`에 포함했다. 고정 원본 커밋·SHA-256은 같은 폴더의 README에 기록한다. 앱은 외부 서체 서버를 사용하지 않으며 WebView의 고정 리소스 허용 목록과 `font/woff2` MIME으로 내장 서체를 제공한다. 로딩 중에는 시스템 서체로 표시한다.

2026-10-01 소스 검증에서 실제 SpaceGrotesk-Bold 글리프 사용, 320/360/393px 헤더 배치, 영어/한국어 연결 상태 표시와 기존 렌더러 검증을 확인했다. 2026-10-02 빌드한 0.9.0 APK에 포함했으며 실제 Android WebView 서체 로딩은 설치 후 확인한다.

## 아이콘

세로 축과 두 코드 꺾쇠를 결합해 B를 만드는 심벌이다. 서로 다른 작업 흐름을 한곳에서 다루는 Bibimer의 의미를 민트·밝은 중성색 두 부분으로 표현한다. 음식 그림이나 단순 `b.` 대신 작은 크기에서도 구별되는 기하학적 형태를 사용한다.

앱 안의 `brand.svg`와 Android 벡터는 같은 도형을 사용한다. 런처에는 배경·전경을 분리한 적응형 아이콘과 Android 13 이상 테마 아이콘용 단색 레이어를 제공한다. 리소스 빌드와 브라우저 크기별 미리보기는 확인했으며 실제 런처의 마스크·테마 적용은 설치 후 확인한다.

## 참고와 검증

- [Orca 구조화된 Chat UI](https://www.onorca.dev/docs/agents/native-chat): 작은 도구 행, 펼쳐 보는 출력과 파일 변경, 계획 표시를 참고했다. 제공자나 플랫폼 기능이 동일하다고 가정하지 않는다.
- [Paseo](https://paseo.sh/): 워크스페이스와 진행·검토 상태를 구분하는 관리 경험을 참고했다. Bibimer의 기본 실행 환경은 같은 폰의 Termux다.
- [Marked lexer와 토큰](https://marked.js.org/using_pro), [highlight.js API](https://highlightjs.readthedocs.io/en/latest/api.html): 토큰 기반 DOM 렌더링과 명시적 언어 강조에 사용한다.
- [Android 적응형 아이콘](https://developer.android.com/develop/ui/compose/system/icon_design_adaptive): 전경·배경·단색 레이어와 108dp 캔버스 안의 중심 영역을 기준으로 작성했다.

`node scripts/smoke_rendering.cjs`는 통제된 에이전트 이벤트로 서식·코드·diff·계획·스크롤·악성 HTML 비실행·이미지 자동 요청 없음·좁은 화면을 검증한다. `node scripts/smoke_ui.cjs`는 실제 임시 브리지·PTY와 모의 에이전트로 기존 기능을 함께 확인한다. 두 테스트 모두 Android 네이티브 API를 대역으로 사용하며 모델 작업을 보내지 않는다.

`node scripts/smoke_select.cjs`는 실제 화면 자산의 선택 컨트롤을 격리해 긴 목록·키보드·비활성 항목·오래된 선택 차단·중첩 팝업·포커스 복원을 검증한다. 통합 UI 테스트도 모든 선택을 자체 시트로 조작한다.

## GitHub 저장소 가져오기 (2026-10-09 소스)

사이드바 **Project Add**의 폴더 등록 폼 위에 **Import from GitHub**를 제공한다. 자체 대화상자에서 계정 연결·일회용 코드 복사/브라우저 열기, 저장소 목록과 불러온 항목 검색, 상위 폴더 탐색·새 폴더 이름·최종 경로 확인·클론을 이어간다. 영어 기본값과 한국어 표시를 지원한다. 기존 프로젝트 폴더 탐색기를 상위 폴더 선택에 재사용하되 기존 등록 폼의 경로는 변경하지 않는다.

저장소는 이름·설명·공개/비공개·보관 여부와 선택 상태를 표시한다. 설명·폴더명은 텍스트로 출력한다. 아래 Recent imports에서 단계·대상 경로·실패 안내·클론 취소·완료 프로젝트 열기를 제공한다. 진행 중 중복 클론을 막고 수락 여부가 불명확한 요청은 입력을 유지한 채 **Check / retry import**로 같은 요청을 확인한다. 현재 가져오기 화면에서 요청한 클론은 프로젝트 등록까지 완료되면 해당 프로젝트를 열고 가져오기 창과 사이드바를 닫는다. 응답 유실 후 같은 요청을 회복했을 때도 한 번만 전환한다. 화면 닫기는 작업 취소가 아니며 닫은 뒤 완료한 작업·이전 가져오기 기록은 자동 전환하지 않고 완료 프로젝트 열기를 사용한다. 실패·취소·등록 중에는 전환하지 않고, 프로젝트 열기 실패 시 수동 재시도를 제공한다. 에이전트 세션을 자동 시작하거나 기존 프로세스를 종료하지 않는다.

320px 한국어·393px 영어 브라우저 레이아웃과 기존 입력 초안/세션 보존을 확인했다. Android 화면·키보드·외부 브라우저 전환은 APK 반영 후 검증한다.

## 민트 티타늄 로고 (2026-10-09 소스 / APK 대기)

사용자가 선택한 민트 티타늄 시안을 앱 아이콘과 대문자 **BIBIMER** 텍스트 로고에 적용한다. 심벌의 기존 각진 B 경로와 내장 Space Grotesk Bold를 유지하고 옅은 민트색 하이라이트·짙은 티타늄 반사·아래쪽 두께를 더했다. 화면의 나머지 색상과 배치는 유지한다.

앱의 `brand.svg`는 금속 표면/모서리 그라데이션과 미세 질감·그림자를 사용한다. 워드마크는 CSS 텍스트 그라데이션으로 표시하고 미지원/고대비 환경에 단색 fallback을 둔다. Android는 벡터 그라데이션·겹친 경로로 질감과 그림자를 단순화하며 배경/전경을 분리한다. 전경은 중심 54dp 기준 0.82배로 축소해 주요 형태/테두리를 반경 33dp 안에 둔다. 테마 아이콘에는 별도 단색 전경을 사용한다. Play 아이콘은 플랫폼 마스크 적용을 위한 정사각형 RGBA PNG로 내보낸다.

320px·393px·1440px 브라우저 표시, 내장 서체·고대비 fallback과 Android 리소스 컴파일/링크를 확인했다. 0.15.0 APK에 포함했으며 제조사별 런처 마스크·테마 표시 및 실제 WebView 출력은 설치 후 검증한다. 구현 기준은 [Android VectorDrawable](https://developer.android.com/reference/android/graphics/drawable/VectorDrawable)과 [적응형·단색 아이콘](https://developer.android.com/develop/ui/compose/system/icon_design_adaptive) 공식 문서를 참고했다.
