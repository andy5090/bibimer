# Bibimer 설치 및 사용 안내

## 필요한 앱과 도구

- Bibimer Android 앱: 이 저장소에서 빌드한 `dist/bibimer-debug.apk`.
- 같은 휴대폰의 Termux.
- 브리지용 Python: 설정 파일이 없을 때 설치한다.
- 실제 작업에 사용할 에이전트와 개발 도구: 사용자 프로젝트에 맞게 Termux에 준비한다.

현재는 개발용 APK이며 공개 배포 채널은 없다. APK는 이 저장소의 [빌드 안내](development.md)에 따라 만들 수 있다. APK 설치를 열면 Android의 설치 확인을 기기 화면에서 진행한다.

2026-10-01 현재 테스트 폰에는 0.6.1(versionCode 10)이 설치되어 있다. 최신 파일은 **내 파일 → 다운로드 → Bibimer-0.7.0.apk**다. Codex 세션 저장 통합에는 앱·브리지 0.7.0이 필요하다. 실행 중인 이전 세션을 마친 뒤 최신 설정 파일을 실행하고 브리지를 재시작한다.

## 앱 설정 (0.9.0)

앱은 기기 언어와 관계없이 영어로 시작한다. **Settings → Language → 한국어**를 선택하면 한국어로 바뀌며 다음 실행에도 선택을 유지한다. 영어로 돌아가려면 **설정 → 언어 → English**를 선택한다. 언어 변경은 실행 세션을 종료하거나 작성 중인 입력을 지우지 않는다. 사용자 입력·프로젝트 이름·터미널 출력은 번역하지 않는다.

**Settings(설정) → Enter key(Enter 키)**에서 **New line(줄바꿈)** 또는 **Send(보내기)**를 선택한다. 기본은 줄바꿈이며 이전 설치본에도 저장값이 없으면 적용한다. 선택은 즉시 저장해 앱을 다시 열거나 프로젝트·세션을 바꿔도 유지한다. 줄바꿈 모드는 Send/Queue 버튼으로 전송하고, 보내기 모드는 Enter로 전송한다. Shift/Ctrl/Meta/Alt+Enter는 항상 줄바꿈한다. Chat·PTY 아래 공통 입력창에 적용하며 터미널 직접 입력·특수 Enter 키에는 적용하지 않는다. 설정 화면 왕복은 실행 세션과 입력 초안을 유지한다.

별도 Settings와 Enter 설정은 0.9.0 APK부터 제공한다. 이전 0.8.2 APK는 Setup에 언어 선택이 있고 Enter는 전송이다. Settings·Enter 설정은 앱 업데이트만 필요하다.

소스에는 선택 메뉴를 누르면 앱 내부 하단 목록에서 고르는 UI를 추가했다. 현재 선택에는 체크 표시가 있고 권한 목록에서는 각 모드의 설명도 볼 수 있다. 이 변경은 **다음 요청 빌드에 포함할 예정**이며 기존 0.9.0 APK에는 아직 반영하지 않았다.

아래 안내는 기본 영어 버튼 이름과 한국어 이름을 함께 표기한다. 앱에서 복사하는 브리지 설치·시작 명령은 선택한 언어를 반영한다. 직접 실행하는 브리지 명령은 영어가 기본이며, 한국어 안내는 `BIBIMER_LANGUAGE=ko`를 명령 앞에 붙이거나 브리지의 `--language ko` 옵션으로 선택한다.

## Termux가 없는 경우

Bibimer의 **Setup(준비) → Installation guide(Termux 설치 안내)**에서 [F-Droid의 Termux 페이지](https://f-droid.org/packages/com.termux/)로 이동한다. 설치 후 Termux를 한 번 열고 초기 환경 준비를 마친다. Termux와 플러그인을 설치할 때는 [Termux 공식 설치 문서](https://github.com/termux/termux-app#installation)의 배포처·서명 안내를 따른다.

Bibimer가 Termux를 대신 설치하거나 Android의 설치 확인을 자동으로 처리하지는 않는다. 앱은 설치 안내, 설정 파일, 다음에 실행할 명령을 제공한다. Termux가 없는 새 기기에서 이 과정을 끝까지 진행하는 검증은 남아 있다.

## 브리지 설치

1. Bibimer의 **Setup(준비) → Save setup file(설정 파일 저장)**을 누른다.
2. Android 파일 저장 화면에서 다운로드(`Download`) 폴더를 선택하고 `bibimer-setup.sh` 이름으로 저장한다.
3. Termux에서 다음 명령을 실행하고 파일 접근 허용을 완료한다. 이미 `~/storage/downloads`를 사용할 수 있으면 이 단계는 생략한다.

   ```sh
   termux-setup-storage
   ```

4. 권한 허용이 끝나고 다운로드 폴더가 연결된 뒤 다음 명령을 실행한다.

   ```sh
   bash ~/storage/downloads/bibimer-setup.sh
   ```

   파일을 다른 위치·이름으로 저장했다면 경로를 맞춘다. 같은 이름의 기존 파일 때문에 `(1)` 같은 접미사가 붙지 않았는지도 확인한다.

5. Python이 없으면 Termux 패키지 저장소에서 설치한다. 이어서 브리지를 `~/.local/share/bibimer/`에 설치하고 `~/.local/bin/bibimer-bridge` 실행 파일을 만든다. 프로젝트 파일이나 에이전트 자격 증명은 이 설정 파일에 포함하지 않는다.
6. 브리지가 시작되면 Termux에 표시된 8자리 코드를 Bibimer의 **Connect this app(이 앱 연결)**에 입력한다. 코드는 5분 동안 한 번만 유효하며 5번 틀리면 다시 발급해야 한다.

이후 브리지를 시작하거나 새 연결 코드가 필요할 때는 아래 명령을 사용한다. 앱의 준비 화면에서 각 명령을 복사할 수 있다.

```sh
~/.local/bin/bibimer-bridge start
~/.local/bin/bibimer-bridge pair
~/.local/bin/bibimer-bridge status
```

`start`는 이미 같은 브리지가 실행 중이면 기존 세션을 유지하고 새 연결 코드를 발급한다. 연결 코드는 일반 로그로 출력하지 않으므로 Termux의 대화형 터미널에서 실행한다.

## 기존 버전에서 업데이트

0.3.0은 여러 프로젝트 등록·전환과 프로젝트별 동시 실행을 제공한다. 기존 프로젝트와 연결 정보는 새 브리지가 이어받는다. 프로젝트 전환은 실행을 종료하지 않으며, 브리지 업데이트를 위한 재시작은 모든 프로젝트의 실행 세션을 마친 뒤 진행한다.

0.2.0의 Chat 모드는 새 브리지가 필요하다. APK만 업데이트한 상태에서도 기존 PTY 세션은 계속 사용할 수 있다.

브리지 0.2.0에서 종료된 세션을 남긴 채 재시작하면 Start session이 비활성화되는 문제가 있다. 0.2.1 브리지는 이를 수정했으며 앱 0.2.0과 호환된다. 브리지 업데이트 후 앱에서 **Reconnect(다시 연결)**를 누른다.

1. 새 APK를 설치하고 **Setup → Save setup file(설정 파일 저장)**로 최신 `bibimer-setup.sh`를 저장한다. 같은 이름의 이전 파일을 덮어쓰거나 실행 경로를 새 파일명에 맞춘다.
2. 위 설치 명령을 다시 실행한다. 실행 중인 브리지가 있으면 유지하며 설치 파일만 갱신한다.
3. 기존 작업을 마치고 앱에서 **Stop this session(이 세션 종료)**을 선택한다.
4. Termux에서 `~/.local/bin/bibimer-bridge restart`를 실행한다. Setup의 재시작 명령 복사 버튼도 사용할 수 있다. 저장소에서 직접 실행하는 개발 환경에서는 `python bridge/bibimer_bridge.py restart`를 사용한다.
5. 앱에서 **Reconnect(다시 연결)** 후 사용할 에이전트와 Chat 모드를 선택한다. 기존 연결 토큰은 유지된다.

재시작은 실행 중인 세션이 있으면 거부한다. 0.1.x에서는 상태 파일 잠금과 프로세스 소유권을 확인한 뒤 해당 프로세스만 종료한다. 이때 다른 화면에서 새 세션을 시작하지 않는다. 기기가 이 확인을 지원하지 않으면 자동 종료하지 않고 수동 종료 안내를 표시한다.

## 응답 중 Queue·Steer (앱·브리지 0.9.0)

0.9.0 APK와 `chat_queue`·`codex_steer`를 지원하는 브리지 0.9.0을 함께 사용한다. APK의 Setup에서 최신 설치 파일을 저장하거나 `Download/bibimer-setup-0.9.0.sh`를 실행해 설치한 뒤, 기존 실행 세션을 마치고 브리지를 재시작한다. APK 설치만으로 운영 브리지를 자동 업데이트하지 않는다.

- 응답 중에도 입력창에 작성할 수 있고 **Queue(대기열)**로 다음 작업을 예약한다. Enter 동작을 보내기로 선택한 경우 Enter로도 예약한다. 대기 메시지는 입력창 위에 표시하며 **Remove(취소)**로 개별 삭제한다. Ctrl/Shift+Enter 줄바꿈과 IME 조합 보호는 동일하다.
- Codex의 **Steer(방향 수정)** 버튼은 현재 응답에 지시를 추가한다. 실제 반영은 에이전트의 처리 시점에 따르며, 새 권한/Fast 선택은 다음 응답부터 적용한다. 거절되면 초안을 유지하므로 대기열로 보낼 수 있다. Claude·OpenCode는 Queue를 사용한다.
- 정상 응답 완료 후 대기 순서대로 실행한다. 응답을 중단하거나 실패하면 대기열도 일시정지하며 **Resume queue(대기열 재개)**로 이어간다. 대기 승인은 별도로 직접 처리한다.
- 대기열은 세션별 최대 16개이며 메시지 하나는 UTF-8 16KiB까지다. 앱 재실행·프로젝트 전환에도 브리지가 실행 중이면 유지한다. 세션 종료나 브리지 종료 시에는 대기열을 보존하지 않으므로 필요한 입력은 따로 보관한다.
- 이전 브리지에서는 응답 중 대기열 기능의 업데이트 안내를 표시한다. 준비 상태의 기존 메시지 전송과 입력 작성은 유지한다.

**다음 APK·브리지 적용 대기:** 대기 메시지 오른쪽에도 **Steer(방향 수정)**를 제공한다. Codex가 응답 중이거나 승인 대기 중일 때 선택할 수 있으며, 그 메시지를 현재 응답에 전달한다. 수락 확인 후 해당 항목만 제거하고 입력창의 초안은 유지한다. 거절되면 항목을 남기고 대기열을 일시정지한다. **전달 여부 불명**으로 표시된 항목은 대화를 확인하고 취소한 뒤 대기열을 재개한다. Claude·OpenCode와 미지원 브리지에는 대기열 Steer 버튼을 표시하지 않는다.

## 모델·추론 수준·에이전트 선택 (다음 APK·브리지 적용 대기)

입력창 아래 **Agent(에이전트)**에서 Codex·Claude Code·OpenCode·Terminal을 선택한다. 기존 세션이 있으면 바로 돌아가고 처음 선택한 경우 **Start session**으로 시작한다. 다른 에이전트에서 진행 중인 응답·승인·대기열은 유지된다. 작성 중인 입력과 질문 답변도 프로젝트·에이전트별로 보관한다. 서로 다른 에이전트에 대화 내용을 자동 전달하지 않으며 앱 프로세스 종료 시 입력 초안은 사라진다.

**Model(모델)**과 **Reasoning(추론 수준)**은 실제 에이전트가 제공하는 목록에서 고른다. 추론 수준은 모델마다 다르며 지원하지 않으면 선택할 수 없다. 모델 변경 시 추론 수준을 기본값으로 초기화한다. ↻ 버튼으로 다시 조회할 수 있고 조회 실패·미설치·미지원 브리지는 안내 문구를 확인한다. 새 세션·다른 프로젝트·가져오기에는 해당 에이전트의 마지막 선택을 사용하고 이미 실행 중인 다른 세션의 설정은 바꾸지 않는다. 가져오기에서는 **Session settings** 안에서 모델·추론 수준을 선택한다.

Chat에서 변경한 값은 다음 메시지부터 적용한다. PTY에서는 다음 실행에 적용하며 현재 프로세스 설정은 CLI 자체 메뉴에서 바꾼다. Codex·Claude PTY는 모델/추론 인수를 지원하지만 OpenCode PTY는 모델 인수만 적용한다. OpenCode Chat에서 기본 모델 복원은 새 세션에서 진행하며 명시한 다른 모델로의 변경은 그대로 지원한다. 목록에 있다고 계정의 모델 사용 성공까지 보장하는 것은 아니므로 로그인·제공자 설정 오류는 Termux에서 확인한다.

위 기능은 소스에 반영했으며 **기존 0.9.0 APK·운영 브리지에는 아직 포함하지 않았다.** 사용자의 다음 빌드·브리지 적용 요청 후 사용할 수 있다.

## 세션 권한·Fast 설정 (앱 0.8.2 / 브리지 0.8.1)

프로그램을 고르면 **입력창 아래에 권한 텍스트 메뉴와 번개 아이콘 Fast 칩**이 나타난다. Fast 칩을 누르면 켜짐(민트색·채워진 번개)과 꺼짐(회색·윤곽선 번개)이 전환된다. 설정 화면을 열 필요 없이 바로 바꿀 수 있다. 마지막 선택은 Android 앱에 에이전트별로 저장하여 다른 프로젝트·새 세션·Saved sessions 가져오기에 사용한다. ⓘ와 가져오기 팝업의 Session settings에서도 설명을 보고 선택할 수 있다.

- Codex: Agent default, Read only, Workspace + approvals, YOLO · full access. 읽기·프로젝트 쓰기는 `on-request` 승인을 사용한다. YOLO는 승인과 샌드박스를 해제한다. 대화 중 변경 및 네이티브 기본 권한 복원을 지원한다.
- Claude: Agent default, Ask for approval, Accept edits, Plan mode, Bypass permissions. 다음 SDK 요청에 선택한 모드를 적용한다.
- OpenCode: Agent default, Ask for all tools, Bypass · allow tools. 진행 중인 대화에서는 Ask↔Bypass를 전환한다. 네이티브 세션 API가 규칙을 추가하는 방식이므로 변경 후 Agent default 복원은 새 세션에서 제공한다. 원본 이어하기에 지정한 규칙은 해당 OpenCode 세션에도 남는다.
- Codex Fast: 기본 꺼짐. Chat에서는 다음 입력부터 적용하고 그 선택은 브리지와 앱에 보관하므로 전송 전 앱을 다시 열어도 유지한다. 실제 제공 여부·사용량은 계정과 모델에 따라 다르다. [공식 안내](https://learn.chatgpt.com/docs/agent-configuration/speed)를 참고한다.

하단에 **Next message**가 표시된 Chat 설정은 다음 전송부터 적용한다. 현재 응답·대기 승인·질문·다른 프로젝트의 실행은 유지한다. **Next session**이 표시된 PTY 설정은 다음 세션용이다. 현재 터미널의 권한·속도는 CLI 자체 설정에서 변경하며 Codex는 `/fast`를 사용할 수 있다. CLI에서 직접 바꾼 값은 앱에 자동 동기화하지 않는다.

현재 Chat 권한 변경에는 앱·브리지 0.8.1이 필요하다. 이전 브리지에서는 하단에 Update bridge가 표시되며 기존 메시지 송수신은 계속 사용할 수 있다.

## 서식 있는 대화

프로젝트를 등록한 뒤 **Codex / OpenCode / Claude Code → Chat · formatted text(대화 · 텍스트 서식) → Start session**을 선택한다. 설치된 에이전트의 새 대화를 앱에서 직접 시작한다. Termux의 CLI 설치·로그인·모델 및 권한 설정을 사용하며 앱이 권한 검사를 임의로 해제하지 않는다. Claude 대화에는 아래의 SDK 준비도 필요하다.

- 아래 입력창에 지시를 작성하고 **Send(보내기)**로 전송한다. 기본 Enter는 줄바꿈이며 **Settings → Enter key → Send**를 선택하면 Enter로 전송한다. **Shift+Enter / Ctrl+Enter**는 항상 커서 위치에 줄바꿈을 넣으며 Meta·Alt+Enter도 같은 동작이다. 한글 등 조합 중인 Enter는 전송하지 않는다. 이 동작은 PTY 아래의 공통 입력창에도 적용된다.
- 응답의 제목·목록·표·코드 블록을 표시하며 코드 블록을 복사할 수 있다. 명령 실행 결과와 파일 변경은 상세를 펼쳐 확인한다. HTML 실행과 외부 콘텐츠 로딩은 지원하지 않는다.
- 에이전트가 요청하면 **Approve once(이번만 승인) / Decline(거절)** 또는 질문의 선택지·자유 입력으로 응답한다. 복수 선택 질문은 여러 선택지를 고를 수 있으며 선택지를 누르는 것만으로 제출하지 않는다. 자유 입력 가능 여부는 에이전트의 요청을 따른다. 미지원 요청은 승인하지 않고 안내한다.
- **Interrupt response(응답 중단)**는 현재 응답만 중단한다. 세션은 다음 지시를 받을 수 있고 작성 중인 입력도 유지한다.
- 앱 재접속 시 같은 프로세스의 대화와 대기 중인 요청을 복구한다. 0.7.0부터 Codex 새 Chat도 CLI와 같은 저장소에 남는다. OpenCode·Claude의 새 대화도 각 도구의 저장 규칙을 따른다. 저장된 세션은 아래의 가져오기 기능으로 다시 열 수 있다.

세 에이전트 모두 **Terminal · PTY**도 선택할 수 있다. 셸은 PTY만 제공하며 실행 중인 PTY를 Chat으로 변환하지는 않는다.

## Claude 대화 준비

Termux에서 실행 가능한 Claude Code CLI와 로그인을 먼저 준비한다. 앱의 **Setup**에서 최신 설정 파일을 `bibimer-setup.sh`로 저장하고 Claude 어댑터 설치 명령을 복사하거나 다음을 실행한다.

```sh
BIBIMER_CLAUDE=1 bash ~/storage/downloads/bibimer-setup.sh
```

설정 파일은 필요한 Node.js와 `@anthropic-ai/claude-agent-sdk` 0.3.283을 Bibimer 전용 폴더에 설치한다. Claude CLI를 대신 설치하거나 기존 CLI를 바꾸지는 않는다. 실행 중인 브리지가 있으면 세션을 마친 뒤 위 업데이트 절차에 따라 재시작하고 **Reconnect**를 누른다.

준비 화면은 CLI 없음, SDK 없음, CLI 실행 실패를 구분한다. **Needs repair**라면 Termux에서 `claude --version`부터 확인한다. 현재 테스트 폰의 고장 난 전역 CLI는 아래의 별도 실행 환경으로 대체해 시작할 수 있다. 실제 모델 대화·도구 실행 검증은 남아 있다. 에이전트의 일반 Linux 설치 방법이 Termux에서도 동작한다고 가정하지 않는다.

### 이 폰의 Claude 실행 파일 복구

앱에서 최신 설정 파일을 저장한 뒤 **Copy Claude repair command(Claude 복구 명령 복사)**를 사용한다.

```sh
BIBIMER_CLAUDE_TERMUX=1 bash ~/storage/downloads/bibimer-setup.sh
```

이 경로는 **arm64 Termux에 glibc 로더와 ripgrep이 이미 준비된 경우**를 대상으로 한다. glibc가 없는 환경의 설치까지 자동 처리하지 않으며 선행 조건이 맞지 않으면 안내하고 중단한다. 공식 패키지 2.1.283의 SHA-512를 확인한 뒤 예상 실행 파일만 추출하고 `--version`이 성공한 경우에만 전용 런처를 바꾼다. 경로는 `~/.local/share/bibimer/claude-runtime/claude`이며 기존 전역 CLI·자격 증명은 유지한다. 로그인은 이 런처를 Termux에서 직접 실행해 진행한다.

현재 기기의 실행 확인을 Android 전체 지원으로 일반화하지 않는다. [Claude 공식 설치 문서](https://code.claude.com/docs/en/setup)의 지원 플랫폼에는 Android가 명시되어 있지 않다.

## 저장된 세션 가져오기

1. 기존 세션의 작업 폴더를 **Project Add → Browse**로 등록하거나 상단에서 해당 프로젝트를 선택한다.
2. 해당 프로젝트에 실행 중인 Bibimer 세션이 없는 상태에서 **Saved sessions(저장된 세션)**을 누르고 Codex·OpenCode·Claude 중 에이전트를 선택한다.
3. 최근 순 목록에서 세션을 선택한다. **Search(검색)**는 제목의 대소문자를 구분하며 **Load more(더 보기)**로 다음 목록을 읽는다.
4. 기본 **Continue original(원본 이어하기)**는 같은 세션 ID로 이어간다. 별도 대화가 필요하거나 원본을 다른 CLI에서 사용 중이면 **Import a copy(복사해서 가져오기)**를 선택한다.
5. **Open selected session(선택한 세션 열기)**을 누르고 이전 기록이 표시되면 후속 지시를 보낸다. 가져오기 자체로 모델 요청을 보내지 않는다.

선택한 에이전트에서 현재 프로젝트와 작업 폴더가 같은 저장 기록을 표시한다. 비어 있다면 에이전트·작업 폴더·검색어를 확인한다. 보관·숨김·임시 세션은 제공자가 공개하는 목록에 따라 제외한다. Codex 새 Chat은 첫 입력 이후 같은 `$CODEX_HOME`(기본 `~/.codex`)의 CLI 목록에도 나타난다. 0.6.x 이전에 시작한 임시 대화는 자동 변환되지 않는다. 가져온 원본과 복사본의 기록은 각 에이전트가 관리한다. 화면은 최근 최대 50항목을 미리 보여주며 전체 과거 기록을 탐색하는 기능은 아직 없다. OpenCode·Claude 목록 조회는 최대 10,000건으로 제한하고, Claude의 64MiB를 초과한 기록은 CLI에서 열도록 안내한다. 미리보기만 실패하고 맥락 복원이 완료되었다면 안내 후 후속 입력이 가능하다.

실행 중인 외부 CLI의 터미널 화면에 붙는 기능은 아니다. 다른 CLI에서 원본을 사용 중이면 **복사해서 가져오기**를 사용한다. 외부 프로세스의 실행 상태를 완전히 탐지하지 못하므로 원본 이어하기 전에 해당 CLI에서 작업을 마친다. 과거 승인 요청은 활성화되지 않으며 새 작업의 승인·질문만 직접 응답한다.

오래된 브리지는 업데이트 안내를 표시한다. 에이전트 업데이트 안내가 나오면 해당 CLI의 호환 버전을 확인한다. 현재 폰의 실제 세션 검증 버전은 Codex 0.156.1, OpenCode 1.17.13이다. Claude SDK의 기록 조회·복사는 통제된 기록으로 검증했으며 별도 Claude 실행 환경의 버전·SDK 연결·PTY 출력도 확인했다. 실제 모델 작업은 미검증이다.

## Codex CLI와 오가기

앱의 Codex 대화에서 **Resume in CLI(CLI에서 이어하기)**를 누르면 `codex resume '<세션 ID>' --cd '<프로젝트 경로>'`를 복사한다. 앱에서 **Stop this session**을 누른 뒤 Termux에서 실행한다. CLI에서 작업을 마치면 앱의 **Saved sessions → Codex → Continue original**로 같은 대화를 다시 연다. 목록의 폴더와 Codex 저장소가 같아야 한다. 다른 `CODEX_HOME`을 사용하는 CLI는 별도 환경이다.

0.6.x의 새 Codex Chat은 임시 대화였으므로 종료 뒤 기록이 없을 수 있다. 이번에 발견한 이전 앱 대화는 남아 있던 표시 기록을 비공개 복구 파일로 보존했으며 전체 모델 맥락을 완전히 복원한 것은 아니다.

## 응답 읽기

0.4.0 Chat은 중첩 목록·체크리스트·표와 코드 구문 강조를 제공한다. 코드의 **Copy(복사)**로 코드만 복사하고 **Wrap(줄바꿈)**으로 가로 스크롤과 자동 줄바꿈을 전환한다. 명령·도구 행을 누르면 출력이, 파일 변경 행을 누르면 파일별 diff가 펼쳐진다. 계획은 완료·진행·예정 단계로 표시한다.

이전 답변을 읽을 때 새 출력이 와도 위치를 유지한다. **Jump to latest(최신 응답으로)**를 누르면 마지막 응답으로 돌아간다. 외부 링크는 브라우저로 열고, 파일 경로 링크는 경로를 복사한다. 이미지는 자동으로 불러오지 않으며 설명·참조 링크로 표시한다.

## 프로젝트와 첫 실행

연결 후 **Work(작업)** 화면에서 `~/projects/my-project` 같은 Termux 경로를 등록한다. 새 폴더가 필요하면 **Create the folder if it does not exist(폴더가 없으면 새로 만들기)**를 선택한다.

기존 폴더는 **Add(추가) → Browse(찾아보기)**로 불러온다. 폴더 이름을 눌러 들어간 뒤 **Select folder(폴더 선택) → Save project(프로젝트 등록)**을 누른다. 입력한 경로가 없으면 Termux 홈에서 탐색을 시작한다. **Home(홈)**·**Up one level(상위 폴더)**·**Show hidden folders(숨김 폴더 표시)**를 사용하고 목록이 길면 **Load more(더 보기)**로 이어서 읽는다. 숨김 폴더는 기본적으로 표시하지 않는다. 폴더 선택은 파일을 복사하거나 새 폴더를 만들지 않는다.

목록은 같은 폰의 Termux에서 접근할 수 있는 폴더다. 읽기 전용 폴더는 탐색할 수 있지만 프로젝트로 선택할 수 없다. 접근 오류가 나면 홈으로 돌아가거나 폴더 권한을 확인한 뒤 다시 시도한다. 오래된 브리지에서는 업데이트 안내를 표시하며 경로 직접 입력은 계속 사용할 수 있다.

다른 프로젝트는 상단 **Project Add(프로젝트 추가)**로 등록한다. 프로젝트 선택 메뉴에서 작업할 폴더를 바꾸며 각 프로젝트의 선택된 세션 상태도 볼 수 있다. 배포된 0.9.0은 프로젝트당 세션 하나를 실행하며, 다음 빌드용 소스는 프로젝트·에이전트별 세션 하나를 실행할 수 있다. 전환해도 실행 중인 작업과 작성 중인 입력·질문 답변을 유지한다. 초안은 앱 화면 메모리에만 보관하므로 앱 프로세스가 종료되면 복원하지 않는다.

처음에는 **Terminal(터미널)**을 선택하고 **Start session(새 세션 시작)**을 누르면 셸의 출력·입력을 확인할 수 있다. 화면 아래 입력창에 명령을 입력하고 **Send(보내기)**를 누른다. Esc, Tab, 방향키, Ctrl+C, Enter 버튼으로 대화형 프로그램에도 입력할 수 있다.

PTY는 ANSI 색상(16색·256색·트루컬러), 굵은 글씨와 ASCII 도형을 표시한다. 프로그램이 출력한 터미널 제어 시퀀스는 xterm.js가 처리한다.

Codex·OpenCode·Claude Code는 Termux에서 실행 가능하게 설치하고 로그인·모델 설정을 마친 뒤 선택한다. 준비 화면에 각 제품의 설치 문서 링크가 있다. OpenCode의 새 Chat과 PTY는 별도 Bibimer SDK 없이 설치된 `opencode` 명령을 사용한다. 해당 문서의 일반 Linux 설치 절차가 Android/Termux에서도 동작한다고 가정하지 않는다.

현재 기기에서는 이미 설치된 Termux용 Codex 배포본의 대화형 PTY 시작 화면과 App Server 대화 초기화를 확인했다. 새 사용자를 위한 에이전트 설치 경로와 실제 모델 작업은 별도 검증 대상이다. 계정 키나 토큰은 Bibimer의 프로젝트 설정에 입력하지 않는다.

## 작업 이어가기와 종료

- 앱 화면 이동·닫기는 세션 종료를 요청하지 않는다. 브리지가 살아 있다면 앱을 다시 열어 같은 세션의 최근 출력을 확인하고 입력을 이어갈 수 있다.
- **Connected(기기 연결됨) / Disconnected(연결 끊김)**는 화면 연결 상태다. 연결이 끊기면 프로세스 상태는 마지막 확인 값으로 표시한다.
- **Stop this session(이 세션 종료)**는 확인 후 해당 세션과 일반적인 하위 작업을 중지한다. 다른 프로젝트의 실행은 유지한다. Ctrl+C는 현재 전경 작업에 인터럽트를 전달한다.
- Android가 Termux나 브리지를 종료하면 기존 프로세스에 다시 접근하지 못할 수 있다. 브리지 재시작 시 이전 실행을 **Session lost(세션 유실)**로 표시한다.
- 최근 출력은 메모리에 1MiB까지 유지한다. 오래된 출력이 생략되면 표시하며, 브리지 재시작 후 출력은 복원하지 않는다.

## 연결이 안 될 때

Termux에서 `status`로 브리지 연결 가능 여부를 확인하고, 실행되지 않았다면 `start`를 사용한다. 코드가 만료되었다면 `pair`로 새 코드를 발급한다. 포트 `8765`를 다른 프로그램이 사용하고 있으면 기본 앱 연결을 시작할 수 없다.

Android의 화면 잠금·배터리 제한·프로세스 종료에 따른 동작은 기기별 확인이 필요하다. [Termux 공식 저장소](https://github.com/termux/termux-app)의 Android 프로세스 제약 안내도 참고한다. Bibimer는 OS가 종료한 프로세스의 생존을 보장하지 않는다.
