# Bibimer 초기 검증 계획

## 현재 진행 상태

2026-09-13에 Android 앱과 Termux 브리지의 첫 구현 및 APK 빌드를 마쳤다. 0.2.0은 영어 기본·한국어 지원과 Codex 대화 모드·PTY 터미널을 함께 제공한다. 현재 폰의 Termux에서 브리지 테스트 25개와 두 언어의 대화·PTY 화면 연결 테스트를 통과했으며, 앞선 구현에서 설치된 Codex의 시작·재접속·종료도 확인했다. 기존 0.1.0 앱 설치는 패키지 조회로 확인했다. 화면 테스트의 Android 네이티브 부분은 어댑터를 사용했으므로 아래의 실제 Android 앱 통과 기준은 아직 완료가 아니다.

다음 확인은 APK 설치·WebView 실행·Termux 연결과 화면 잠금·재실행이다. Termux가 없는 사용자를 위한 설치 가이드와 자체 포함 설정 파일을 구현했으며, 새 기기에서 설치부터 실행까지 진행하는 확인도 별도로 남아 있다. 자세한 결과와 재현 명령은 [개발 및 검증](development.md)에 기록했다.

## 검증 목표

휴대폰에 설치한 Bibimer Android 앱에서 같은 기기의 Termux를 통해 직접 개발을 진행하는 흐름을 검증한다. 프로젝트 파일과 에이전트 CLI, 개발 명령은 해당 휴대폰에 두며, 별도의 개발 PC나 원격 개발 호스트를 필수 실행 환경으로 두지 않는다.

Orca·Paseo의 프로젝트·에이전트 관리 경험을 참고하되, 첫 검증 범위는 프로젝트 하나·에이전트 하나의 실행, 입출력, 재접속으로 유지한다.

## 검증할 질문

1. 현재 기기의 Android·Termux 설치 환경에서 외부 앱이 브리지를 어떻게 시작하거나 연결할 수 있는가?
2. 별도 Android 앱에서 Termux 브리지로 인증된 로컬 연결을 만들 수 있는가?
3. 앱 연결이 끊겨도 Termux 내부 프로세스를 유지하고 기존 출력 및 입력 스트림에 재접속할 수 있는가?
4. Codex CLI 또는 Claude Code 중 현재 기기에서 실행 가능한 에이전트는 무엇인가?
5. 터치 키보드 입력, 터미널 크기 변경, 인터럽트 전달을 안정적으로 처리할 수 있는가?
6. 앱 화면 종료, 화면 잠금, OS에 의한 프로세스 종료를 각각 어떻게 표시하고 복구할 것인가?
7. 실제 Android 앱을 기기에 설치하고, 같은 휴대폰의 Termux에서 실행한 작업의 출력 확인과 후속 입력을 앱에서 이어갈 수 있는가?

## 검증 순서

우선 설치 환경과 사용 가능한 도구를 읽기 전용으로 조사한다. Termux 및 Android 공식 문서에서 연동·권한·프로세스 제약을 확인한 후 작은 연결 실험을 만든다.

첫 실험에서는 Termux 브리지를 수동으로 시작해도 된다. 최소 Android 앱을 같은 휴대폰에 설치하고, 로컬 연결, Termux 내 명령 실행, 출력 수신, 입력 전송이 되는지 검증한다. 다음으로 연결 해제와 재접속을 시험하고 실제 에이전트 하나를 연결한다. 성공한 통신 및 세션 모델을 기준으로 앱과 브리지의 구현 구조를 확정한다.

## 통과 기준

- 같은 휴대폰에 설치한 실제 Android 앱과 Termux로 아래 흐름을 검증한다. 별도의 PC나 원격 개발 호스트에 개발 프로세스 실행을 맡기지 않는다.
- 같은 휴대폰의 Termux에 등록한 프로젝트 경로에서 지정한 프로세스가 실행된다.
- 앱에서 출력 확인과 입력 전송이 가능하다.
- 앱 연결을 끊었다가 연결해도 같은 살아 있는 세션에 접근한다.
- 프로세스가 종료되면 실제 종료 상태가 표시된다.
- 명시적 중지 시 대상 세션만 중지된다.
- 브리지에 인증 없이 명령을 실행할 수 없다.

OS에 의한 Termux 프로세스 종료 후에도 세션이 살아 있다고 가정하지 않는다. 이 경우에는 세션 유실을 알리고 새 실행 또는 에이전트 자체 복구 기능을 제안할 수 있어야 한다.
