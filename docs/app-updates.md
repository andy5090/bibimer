# 앱 업데이트 감지

## 사용자 흐름

Bibimer는 Google Play 공식 `AppUpdateManager.getAppUpdateInfo()`로 현재 계정에 제공되는 새 버전을 확인한다. 새 버전이 있으면 작은 안내와 **Google Play에서 보기 / 나중에**를 제공한다. 사용자가 선택했을 때만 고정된 `app.bibimer` 스토어 페이지를 연다. Play 앱을 열 수 없으면 같은 공식 HTTPS 페이지를 브라우저로 연다. 앱 안에서 다운로드·설치·재시작을 호출하지 않는다.

설정의 **앱 업데이트**에서 설치된 버전, 확인 상태, 수동 확인과 스토어 이동을 제공한다. 확인 실패·지원되지 않는 설치·확인 중을 새 버전 없음과 구분한다. 이 기능은 내부 테스트 0.20.0(37)부터 제공한다.

## 확인과 상태 관리

- 정상 모드의 Activity 복귀에서 자동 확인한다. 성공 후 24시간, 실패 후 15분 동안 자동 재확인을 제한한다. 설정의 수동 확인은 간격을 우회하되 진행 중 요청은 중복하지 않는다.
- Google Play 설치 출처에서만 SDK를 조회한다. 개발용 APK 등 다른 설치는 자동 확인 불가 안내와 스토어 링크를 제공한다. 개발 인증서·업로드 인증서와 Play 배포 인증서를 혼동하지 않는다.
- Play가 업데이트 가능이라고 응답하고 제공 코드가 설치 코드보다 큰 경우에만 새 버전으로 표시한다. API 오류·알 수 없는 응답을 최신 버전이라고 표시하지 않는다.
- `나중에`는 해당 버전의 안내를 24시간 숨긴다. 설정의 수동 확인·스토어 이동은 계속 사용할 수 있다. 더 높은 새 버전은 다시 안내한다.
- 설치 코드, 제공 코드, 마지막 확인/안내 숨김 시각과 상태만 비공개 설정에 저장한다. 계정 ID·인증 정보·프로젝트 경로·대화 내용은 업데이트 설정에 저장하지 않는다. 설치 코드가 바뀌면 이전 확인 캐시를 사용하지 않는다.
- 종료된 Activity나 심사용 예제 전환 이전의 늦은 응답을 무시한다. 예제 모드에서는 실제 Play 요청·스토어 이동·일반 업데이트 설정 변경을 차단한다.
- 안내와 스토어 페이지 이동은 세션·초안·승인을 수정하거나 Termux 프로세스를 재시작하지 않는다. 사용자가 Play에서 실제 설치를 진행하면 Android가 앱 프로세스를 종료할 수 있다. 기존 RAM 초안의 설치 후 복원을 새로 보장하는 기능은 아니다.

## Termux 브리지

별도 설정 카드에서 연결된 브리지와 앱에 포함된 설치 파일의 브리지 버전을 비교한다. 연결되지 않았거나 버전을 해석할 수 없으면 확인 불가로 표시한다. 연결 버전이 낮으면 설치 안내로 이동할 수 있다. 설치 파일 실행이나 운영 브리지/세션 종료·재시작은 자동으로 하지 않는다.

포함된 버전은 `bridge/bibimer_bridge.py`의 `VERSION`을 빌드 시 `ReviewAccessConfig.BRIDGE_VERSION`으로 생성한다. 앱에 수동으로 같은 버전 문자열을 중복 관리하지 않는다.

## 구현과 검증

- Android: `AppUpdates.java`, `MainActivity.java`의 제한된 Native API와 공식 스토어 주소, Play 패키지 조회/SDK manifest 항목.
- UI: 기존 `app.js`·설정 카드·공지 영역·버튼 스타일을 재사용한다. 새 JS 의존성이나 별도 화면/선택기를 추가하지 않았다. 새17개 문구를 포함해608키×10언어다.
- 빌드: [SDK 구성](../scripts/README-play-sdk.md) 참조. 공식 `app-update:2.1.0`과 선언된 전이 의존성31개를 Google Maven의 고정 버전·SHA256으로 검증한다. 자체 AAPT2/javac/D8 경로에 필요한 리소스·R클래스·manifest·라이선스를 함께 처리한다.
- Python25개(업데이트 상태 JVM122단언 포함), Node 업데이트 UI·기존 언어/프로젝트/초안/심사 접근 회귀, Android 리소스·전체Java·DEX 컴파일을 통과했다. D8는 의존성의 오래된 디버그 정보2곳을 제거한다는 안내를 남기며 컴파일 오류는 없다.
- 격리된 Native API 대역과 실제 앱 UI로320px10언어,393px한국어,1400px영어, 안내 닫기·초안 유지·수동 확인·명시적 스토어 동작·브리지 안내 이동을 확인했다. 콘솔 오류/가로 넘침 없음. `dist/app-updates/`, `.tools/app-updates-compile.log`.

```sh
python3 -m unittest discover -s scripts/tests -p 'test_*.py'
node scripts/tests/test_app_updates_ui.cjs
node scripts/tests/test_i18n.cjs
```

2026-10-15에 0.20.0(37)을 빌드·서명해 내부 테스트에 게시했다. 에뮬레이터 업데이트 설치·설정/수동 확인·실제 Play 앱 열기·재실행은 확인했으나 Play 로그인 계정의 제공 버전 응답은 미검증이다.37을 Play로 설치한 뒤, 더 높은 versionCode의 새 버전을 같은 테스터에게 제공해 **이전 기능 포함 버전의 감지 → 사용자 선택 → 스토어 업데이트 표시**를 확인해야 한다. 사이드로드나 SDK 대역 검사를 실제 Play 설치본 검증으로 표현하지 않는다.

공식 근거: [Java 업데이트 API](https://developer.android.com/guide/playcore/in-app-updates/kotlin-java), [업데이트 테스트 조건](https://developer.android.com/guide/playcore/in-app-updates/test).
